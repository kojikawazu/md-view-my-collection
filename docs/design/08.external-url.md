# 外部URL管理機能 — 設計書

## 概要

仕様書（`docs/spec/08.external-url.md`）の機能を実装するための技術設計。
既存の APIルート・コンポーネント・hooks パターンを踏襲する。

## データ設計

### ExternalUrl テーブル

> 既存スキーマに合わせ、テーブル名は PascalCase、カラム名は camelCase とする（`@@map` / `@map` 不使用）。

| カラム | 型 | 制約 | 説明 |
|---|---|---|---|
| id | UUID | PK, DEFAULT uuid() | 一意識別子 |
| reportId | UUID | FK → Report.id, ON DELETE CASCADE, NOT NULL | 紐付け先レポート |
| url | TEXT | NOT NULL | 外部URL |
| label | TEXT | NULLABLE | 表示ラベル |
| createdAt | TIMESTAMPTZ | NOT NULL, DEFAULT NOW() | 登録日時 |

**インデックス:**
- `ExternalUrl_reportId_idx` ON (`reportId`)

### RLSポリシー

| 操作 | ポリシー名 | 条件 |
|---|---|---|
| SELECT | `external_url_select` | `true`（誰でも） |
| INSERT | `external_url_insert` | `auth.uid() IS NOT NULL` |
| UPDATE | `external_url_update` | `auth.uid() IS NOT NULL` |
| DELETE | `external_url_delete` | `auth.uid() IS NOT NULL` |

### DB作成手順

> DBマイグレーション禁止ルールに従い、テーブル作成は別プロジェクトで行う。

1. 別プロジェクトで `ExternalUrl` テーブル + RLS + インデックスを作成
2. `cd front && npx prisma db pull` で `schema.prisma` に反映
3. `npx prisma generate` でクライアント再生成

### Prismaスキーマ（想定）

```prisma
model ExternalUrl {
  id        String   @id @default(uuid())
  reportId  String
  url       String
  label     String?
  createdAt DateTime @default(now())

  Report    Report   @relation(fields: [reportId], references: [id], onDelete: Cascade)

  @@index([reportId])
}

// Report モデルに追加
model Report {
  // ... existing fields ...
  ExternalUrl ExternalUrl[]
}
```

> 既存の `ReportTagMapping` と同じく、`@@map` / `@map` は使用しない。
> `prisma db pull` 時に Prisma が自動生成する形式に準拠する。

## API設計

### 読み取り（既存エンドポイント拡張）

**GET /api/reports**
- Prisma `include` に `ExternalUrl` を追加
- レスポンスの各レポートに `externalUrls: ExternalUrlItem[]` を含める
- externalUrls は軽量（URL + ラベルのみ）のため一覧APIにも含める

**GET /api/reports/[id]**
- 同上

**変換関数への追加:**

一覧API用の `toReportListItem()` と詳細API用の `toReportItem()` の両方に externalUrls マッピングを追加する。

```typescript
// 共通のマッピングヘルパー
const mapExternalUrls = (urls: ExternalUrl[]) =>
  urls.map((eu) => ({ id: eu.id, url: eu.url, label: eu.label }));

// toReportItem（詳細用・content含む）
const toReportItem = (report: ReportWithRelations) => ({
  // ... existing mapping ...
  externalUrls: mapExternalUrls(report.ExternalUrl ?? []),
});

// toReportListItem（一覧用・content除外）
const toReportListItem = (report: ReportListRow) => ({
  // ... existing mapping ...
  externalUrls: mapExternalUrls(report.ExternalUrl ?? []),
});
```

### 書き込み（既存エンドポイント拡張）

**POST /api/reports**
- requestBody に `externalUrls?: { url: string; label?: string }[]` を追加（省略時は空配列扱い）
- トランザクション内で Report 作成後に ExternalUrl を bulk insert

```typescript
// トランザクション内（既存の TagMapping 同期の後に追加）
if (externalUrls.length > 0) {
  await tx.externalUrl.createMany({
    data: externalUrls.map((eu) => ({
      reportId: report.id,
      url: eu.url,
      label: eu.label || null,
    })),
  });
}
```

**PATCH /api/reports/[id]**
- requestBody に `externalUrls?: { url: string; label?: string }[]` を追加
- トランザクション内で全件置換（delete + insert）

```typescript
// トランザクション内（TagMapping 同期パターンと同じ）
await tx.externalUrl.deleteMany({ where: { reportId: id } });
if (externalUrls.length > 0) {
  await tx.externalUrl.createMany({
    data: externalUrls.map((eu) => ({
      reportId: id,
      url: eu.url,
      label: eu.label || null,
    })),
  });
}
```

**DELETE /api/reports/[id]**
- 変更なし（ON DELETE CASCADE で ExternalUrl は自動削除）

### バリデーション（validation.ts 追加）

既存の `fieldErrors: Record<string, string>` 契約に合わせ、行単位のdot-notationキーでエラーを返す。

```typescript
const MAX_LABEL_LENGTH = 200;
const URL_PATTERN = /^https?:\/\//;

/** 外部URL配列のバリデーション */
export function validateExternalUrls(
  urls: unknown,
): { data: ExternalUrlInput[]; errors: Record<string, string> } {
  const errors: Record<string, string> = {};
  const data: ExternalUrlInput[] = [];

  if (!Array.isArray(urls)) return { data, errors };

  for (let i = 0; i < urls.length; i++) {
    const item = urls[i];
    const url = typeof item?.url === 'string' ? item.url.trim() : '';
    const label = typeof item?.label === 'string' ? item.label.trim() : '';

    if (!url) {
      errors[`externalUrls.${i}.url`] = 'URLは必須です。';
    } else if (!URL_PATTERN.test(url)) {
      errors[`externalUrls.${i}.url`] = 'URLはhttp://またはhttps://で始まる必要があります。';
    }

    if (label.length > MAX_LABEL_LENGTH) {
      errors[`externalUrls.${i}.label`] = `ラベルは${MAX_LABEL_LENGTH}文字以内です。`;
    }

    data.push({ url, label });
  }

  return { data, errors };
}
```

**フォーム側のエラー表示:**

`useReportForm` は `fieldErrors` を `Record<string, string>` で管理済み。
`ExternalUrlInput` molecule は `fieldErrors[`externalUrls.${index}.url`]` でエラーメッセージを取得・表示する。

```typescript
// ExternalUrlFieldList 内で
<ExternalUrlInput
  urlError={fieldErrors[`externalUrls.${index}.url`]}
  labelError={fieldErrors[`externalUrls.${index}.label`]}
  ...
/>
```

## ローカルモード対応（E2E用）

E2Eは `NEXT_PUBLIC_DATA_MODE=local` で動作するため、ローカルモードでも ExternalUrl を扱えるようにする。

- `localStorage` の `espresso_reports` に格納するレポートオブジェクトに `externalUrls` フィールドを追加
- AppStateProvider のローカルモード処理で externalUrls の保存・読み取りを対応
- テストデータ（fixture）に externalUrls を含むレポートと含まないレポートを用意

## 設計判断

### DJ-1: URL同期は「全件置換」パターンを採用

TagMapping 同期と同じく、更新時は既存レコードを全件削除 → 再挿入する。
**理由:** 差分計算が不要でシンプル。URL件数は1レポートあたり数件想定であり、パフォーマンス問題なし。

### DJ-2: 専用APIエンドポイントは設けない

ExternalUrl は常に Report と一緒に操作されるため、既存の `/api/reports` エンドポイントを拡張する。
`/api/external-urls` のような独立エンドポイントは不要。

### DJ-3: 一覧APIにも externalUrls を含める

content（2.2MB）と異なり、externalUrls は URL + ラベルのみで軽量。
一覧APIから除外する必要はない。将来的にリンク有無アイコンの表示にも対応可能。

### DJ-4: ラベル未入力時はURL自体をリンクテキストにする

ラベルは任意入力。未入力の場合、URL文字列をそのまま `<a>` のテキストとして表示する。
OGP等からの自動取得は将来拡張とし、今回は実装しない。
